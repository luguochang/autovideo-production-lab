# 标准交付包装配与验证

本文件定义 AutoVideo 的标准交付包，不把“生成了一个 MP4”当作完成。包必须同时保存输入锁、声音合同、字幕对齐、分镜规划、可编辑 HyperFrames 源码、工作台审计快照、QA 收据和复盘记录。

## 生成

```powershell
npm.cmd run video:package -- --project <project-id>
npm.cmd run video:verify-package -- --project <project-id>
```

标准包输出到：

```text
hyperframes-workflow-kit/projects/<project-id>/delivery/standard-package/
```

生成器使用暂存目录和逐文件 SHA-256 校验，验证通过后才替换旧包。包内不复制 `node_modules`；HyperFrames 项目保留 `package.json` / `package-lock.json`，需要编辑时在包内安装锁定依赖即可。

## 包内合同

```text
README.md
PACKAGE_STATUS.json
PACKAGE_MANIFEST.json
project/       正式项目输入、音频、字幕、规划、素材、HyperFrames 源码、QA、内部 MP4
workbench/     项目阶段、版本、审批作用域、失败作业和产物快照
automation/    本次运行使用的脚本、schema、提示词、工作台源码和编译器冻结版本
documentation/ 声音/视频交接、风格合同、SOP、工作台规则
```

`PACKAGE_STATUS.json` 明确区分：

- `internalDeliveryReady`：机器和内部审片包是否可复核；
- `publicReleaseBlocked`：是否仍被人工听审、Studio 全片审片、权利或事实门禁阻塞；
- `unvalidatedInputRoutes`：当前项目之外尚未跑金标的资料包/录音路线；
- `standardizationGaps`：跨项目回归、精确对齐、OCR、Studio 对象回写和批量生产缺口。

## 变更规则

任何 NarrationLock、最终 WAV、alignment、storyboard、Graph IR、素材权利或 HyperFrames 源码变化，都必须重新生成受影响下游并让旧标准包进入 `stale`。人工修改只能通过工作台产物覆盖或 `overrides/overrides.json` 记录，机器回执不可手工改绿。

屏幕文字、人物姿态和场景左右布局使用工作台“画面微调”，按稳定 scene/cue/object ID 写入字段级 overrides。保存和撤销都会保留历史，并只让全片制作及交付下游失效。完整契约见 [`15-工作台画面微调与Overrides.md`](15-工作台画面微调与Overrides.md)。

公开发布门禁通过前，标准包只允许包含明确命名的 `internal-review` MP4，不能生成或伪装 `master.mp4`。
