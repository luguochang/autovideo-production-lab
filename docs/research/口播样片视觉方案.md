# 口播样片视觉方案

> 日期：2026-07-16  
> 输入：`demo/demoText.txt`  
> 范围：只做视觉提案和可执行锚点，不修改口播，不修改主源码，不调用大模型  
> 目标：用同一份已审稿口播，比较三种明显不同的“持续单画板教学”风格

> 实施说明：本文保留的是制作前的概念探索，A/B/C 字母和命名不能作为最终产物索引。实际落地的 E08 候选为 `A-system-map`、`B-whiteboard-mindmap`、`C-diagnostic-console`，以《[demoText 三套连续画板成品与验证](../03-demoText三套成品与验证.md)》和实验目录为准。

## 1. 先给结论

这份口播适合做连续画板，但不适合继续套“每段一页”的视频模板。全文应当只存在一个长期存活的世界画板、一个相机、一个背景和一个字幕层。每讲完一部分，旧对象缩小、归档或重组，新对象在画板其他区域展开；任何时刻都不卸载整屏内容，也不让背景变黑。

建议比较以下三套成品样片：

1. **A：纸张工程白板**。最接近用户给出的参考视频，像老师拿着记号笔在一张大纸上推演，优先制作。
2. **B：深色系统剖面**。像拆开一台 Agent 机器检查内部结构，技术感最强，用来判断用户是否更喜欢高密度工程视觉。
3. **C：能力进化路线图**。镜头沿一条持续生长的路线经过五个站点，最容易标准化和自动生成。

为了只比较风格，不让内容差异干扰判断，三条首轮样片应使用完全相同的连续原文窗口：`P05-P06 / [308,492)`，即从“`五个原因`”到“`状态管理问题。`”，共 184 个 Unicode code point。按约 240-330 字/分钟估算，这一窗口约 33-46 秒，能同时验证总览、分支展开、对象归档、相机平移和长列表排布。

全文共有 1550 个 Unicode code point。按约 240-330 字/分钟估算，逐字朗读约 4 分 42 秒至 6 分 28 秒，明显不是 30-45 秒口播。技术上可以完整生成，但不建议在风格尚未确认时直接渲染三条 5 分钟成片。先用同稿同段做三条 33-46 秒成品样片，确认风格后再做一条全文版，更容易看出真正的风格差异。

## 4. 三套方案共同遵守的单画板合同

### 4.1 图层和生命周期

```text
sys_caption       固定在视口，不随相机移动
sys_overlay       进度、章节号、轻量聚焦标记，固定在视口
sys_camera        只变换 world，不替换 clip
world_foreground  指针、连线端点和局部强调
world_content     所有知识对象，跨段落长期存在
world_background  纸纹/网格/轨道等持续背景，从第 0 帧到最后一帧
```

硬规则：

- 整条视频只有一个长生命周期 root composition 和一个 `.world`。
- 禁止将 P01-P14 编译成 14 个整页 clip；段落只能拥有稳定 region 和对象。
- `sys_background`、`sys_camera`、`sys_caption` 不允许删除或整体淡出。
- 页面推进只允许 `add/write/move/scale/highlight/connect/replace/remove/camera/pause` 这类原子操作。
- “完成一个知识点”的默认动作是移动到记忆轨道并缩到 `0.58-0.72`，不是让整组消失。
- 全屏从不做 opacity 0；禁止黑底中间帧、`display:none` 切换和空白过场。
- 相机只变换 `.world` 的 `x/y/scale`。背景纸纹可随世界移动，但最底层视口底色必须常驻。
- 所有对象在首轮生成时就获得稳定 `data-ir-id` 和显式 `data-hf-id`，人工编辑以后不按文字反查对象。

### 4.2 9:16 安全区

最终画幅为 1080x1920。不同短视频客户端的按钮位置会变化，因此采用偏保守的通用区：

| 区域 | 最终像素范围 | 用途 |
|---|---|---|
| 全幅出血 | `x 0-1080, y 0-1920` | 背景、纸纹、无语义装饰、连线尾部 |
| 平台硬安全区 | `x 72-888, y 120-1650` | 不应被头像、右侧交互按钮、顶部状态或底部说明遮挡的内容 |
| 教学焦点区 | `x 96-864, y 170-1410` | 当前主标题、图表主体、重要数字、相机目标 |
| 烧录字幕区 | `x 108-852, y 1450-1635` | 最多两行中文字幕，不放当前知识对象 |
| UI 保留区 | `x 888-1080`、`y 0-120`、`y 1650-1920` | 只允许背景和无语义装饰 |

开发预览 720x1280 时按 `2/3` 等比缩放，不另外设计一套坐标。相机每次完成变换后，当前焦点对象的包围盒必须完全落入“教学焦点区”，不能只检查是否仍在画面内。

文字建议以 1080x1920 为准：主命题 82-112 px，章节标题 58-76 px，正文 38-48 px，标签 28-34 px；连续中文正文每行约 12-16 个汉字。屏幕长句优先拆成多个仍引用原文的对象，不缩成手机上不可读的小字。

### 4.3 动画节奏

- 每个知识区遵循 `build 25-30% / breathe 40-50% / resolve 20-30%`，但不把整段内容一起进出。
- 入口一般 0.28-0.58 秒，退出或归档 0.20-0.38 秒，相机移动 0.75-1.20 秒。
- 相机移动时只允许 1 个主对象继续做小幅内部动画，避免整屏同时漂移。
- 每个长句最多 2-3 个语义强调，不做逐字弹跳。百分比、五个原因、Magic/Engineering、成熟度链可以做强强调。
- 重要对象先动，其他对象在 500 ms 内重叠进入；不能按 DOM 顺序机械排队。
- 每 6-12 秒允许一次明显重构，每 15-25 秒安排一次拉远看全局，其余时间让画面停下来供观众阅读。
- 环境运动必须有限、可 seek，强度不超过主体位移的 5%；不使用无限循环、随机数或墙钟时间。
- cue 的开始位置绑定 `Kxx` 字符锚点；Edge TTS 换音色或语速时只重算绝对时间，不重新规划对象。

## 5. 方案 A：纸张工程白板

### 5.1 视觉世界

一张带轻微纤维和定位点的浅色工程纸持续存在。画面不是“手写字体滤镜”，而是清晰印刷体配合真实的笔划、圈画、箭头和便利贴。老师的存在由一个小型记号笔尖/指示圆点表达，不需要生成真人或虚拟主播。

建议色板：纸面 `#F3F4EE`、主墨 `#1A2421`、朱红强调 `#E24A3B`、工程蓝 `#2D67C7`、校验绿 `#208A64`。不使用米色单色主题，不使用紫蓝渐变，不把所有内容装进同样的圆角卡片。

世界画板建议为 2880x6800。顶端是警示与市场现象，中部是“五个原因”总图，五个原因沿左右交错的树枝展开，底部是成熟度链、学习路线和结论。旧区域归档到左右“页边批注”，所以观众一直知道自己在同一张纸上。

推荐使用的 HyperFrames 动作族：`viewport-change`、`svg-path-draw`、`center-outward-expansion`，再加少量与 ASR 锚点同步的关键词强调。实际编码前应加载对应规则全文，并编译成一个 paused GSAP timeline。

## 6. 方案 B：深色系统剖面

### 6.1 视觉世界

整个画板是一台被拆开的 Agent 系统。开头只看到漂亮的外壳和可拖拽节点，随着口播推进，外壳逐层分解，露出模型、API、权限、数据、状态、日志、测试和回滚等内部结构。五个原因不是五张页面，而是同一台机器的五个检查舱。

建议色板：石墨底 `#121817`、浅灰绿字 `#E7EFEB`、信号绿 `#45C79C`、警告黄 `#F0B94E`、故障红 `#EB5B55`、少量冷蓝 `#4F83D8`。禁止全屏线性渐变、随机 glitch 和黑场闪烁；技术感来自结构、线路和状态变化，不来自噪声特效。

世界画板建议为 3200x6200。中心是一条纵向系统脊柱，五个检查舱在左右交错展开，最底部汇成成熟度流水线。背景网格、坐标标记和系统脊柱从第 0 帧持续到最后一帧。

推荐使用的动作族：`viewport-change`、`depth-scatter-assemble`、`svg-path-draw`、ASR 关键词强调。分层拆解只使用确定性索引生成的位移，不使用随机散射。

## 7. 方案 C：能力进化路线图

### 7.1 视觉世界

### 7.5 节奏性格和风险

- 节奏关键词：生长、跟随、到站、展开、折叠。相机移动最多，单个对象动画最少，整体最容易保持自然。
- 首轮 P05-P06 样片可直接从路线总览开始，再进入站点 1；三十多秒内能看见“总览 -> 聚焦 -> 展开 -> 折叠回总览”的完整循环。
- 风险：如果每站都用相同弹出和折叠节奏，会产生模板感。五站应分别使用揭层、承重、翻面、断路、环形检查五种结构动作，只共享路线和相机语法。

## 8. 三套方案对比和推荐顺序

| 维度 | A 纸张工程白板 | B 深色系统剖面 | C 能力进化路线图 |
|---|---|---|---|
| 与参考视频接近度 | 最高 | 中 | 高 |
| “老师在同一画板讲解”感 | 最高 | 中高，偏系统演示 | 高，偏路线推演 |
| 技术视觉冲击力 | 中高 | 最高 | 中 |
| 长达 5 分钟的可读性 | 高 | 中，需控制密度 | 最高 |
| 自动布局难度 | 中 | 高 | 低到中 |
| 用户手工调整难度 | 低，移动便签/线条直观 | 高，模块依赖较多 | 低，调整站点和路径即可 |
| 资产依赖 | SVG 图标和纸纹即可 | SVG 模块、线路和状态图标较多 | 一条主 SVG 路径和站点组件即可 |
| 黑闪风险 | 很低 | 低，严禁 glitch/全屏模糊 | 很低 |
| 适合第一批标准模板 | 是 | 作为高技术感备选 | 是，最利于自动化 |

建议制作顺序为 **A -> C -> B**：

1. A 先验证是否达到用户口中的“一个画板上讲解”。
2. C 验证标准化工作流能否在较少定制下保持自然流动。
3. B 用相同口播检验用户是否愿意用更高密度、更技术化的视觉换取冲击力。

如果只能保留一个主模板，优先 A；如果要建设可批量生成的第二模板，优先 C；B 适合作为科技、系统架构、Agent、RAG 等主题的高级模板，而不是所有口播的默认模板。

## 9. 大模型在这条链路中的边界

这三套首轮样片不需要大模型也能规划和渲染。用户提供的 GPT 前沿模型更适合后续将任意长口播转换成受约束的视觉提案，但不能直接写最终 HTML，也不能接管口播。

推荐调用合同：

```text
输入：NarrationLock + segments + 允许的对象类型 + 选定主题 + 已存在对象摘要
输出：每段 logicalKey、sourceRangeCp、displayTextSourceRangeCp、对象关系、建议 region、motion preset
禁止输出：新口播、改写口播、业务 ID、任意 JS、最终 HTML、用户 patch/lock
```

首版应使用结构化 JSON Schema 和 `displayTextMode: exact-source-only`。模型返回的每个屏幕短语都必须能在锁定文本中按 code point 区间复核；无法复核就拒绝提案。用户在 Studio 修改后形成 patch/lock，后续模型只重算未锁字段。模型密钥只从环境变量或未提交 `.env` 读取，不写入 `/docs`、源码、命令日志或生成物。

## 10. 首轮三条成品样片的统一验收

三条样片必须满足同一组检查，否则风格比较无效：

1. 音频逐字使用 `P05-P06 / [308,492)`，三条音频文件、voice、rate、volume 和 pitch 完全相同。
2. 720x1280 预览和 1080x1920 最终版使用同一布局比例；30 fps，H.264 + AAC。
3. 从第 0 帧到最后一帧只有一个 `.world`，背景和字幕层全程存在。
4. K11、K12、K13、K14、K15 均能从 Edge TTS 边界解析到明确 cue，不能靠人工猜秒数。
5. 至少包含 1 次总览拉远、1 次平移/聚焦、1 次对象缩小归档、1 条 SVG connector/path draw、8 个以上稳定对象。
6. 任何相机停点的当前主对象都在教学焦点区，字幕不遮对象，右侧平台按钮区没有关键信息。
7. 每个可编辑对象都有唯一稳定 `data-ir-id` 和显式 `data-hf-id`；文字查找不作为编辑身份。
8. HyperFrames `check --snapshots` 无运行时、布局和 motion 错误；关键帧截图人工检查首、中、尾和每个相机停点。
9. FFmpeg 检查为 `BLACK_FRAMES=NONE`；另做相邻帧亮度突变扫描，排除非黑色的全屏闪烁。
10. 相机全程只有连续 transform，不允许 clip 交替、全屏 crossfade、glitch、白闪或黑闪。
11. 成片结尾保留已经展开的知识结构，不切到一张孤立 CTA 页。
12. 三条样片各保存 `board.generated.json`、`timeline.json`、静态总览图、关键帧图、MP4、QA 回执和渲染命令到各自 experiment 目录，并在 `/docs` 更新结果。
