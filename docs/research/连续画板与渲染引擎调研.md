# 连续画板与渲染引擎调研

> 调研与本机验证日期：2026-07-16  
> 范围：HyperFrames、Motion Canvas、Revideo、Remotion  
> 目标：已审稿口播驱动、同一大画板对象跨段保留/移动/缩放、相机平移缩放、音频同步、无头渲染、结构化数据驱动和人工微调。

## 1. 结论先行

当前最优主线是：

```text
Canvas IR / Timeline IR（本项目定义，稳定对象 ID）
  -> HyperFrames 0.7.59 适配器
  -> HTML + CSS + SVG + GSAP 连续画板
  -> HyperFrames Studio / SDK 预览与人工覆盖
  -> HyperFrames CLI 无头渲染
  -> FFprobe + blackdetect + 抽帧像素检查
```

选择理由不是“HTML 写起来方便”这么简单，而是 HyperFrames 是四个候选中唯一同时满足以下条件、且已在本机完整跑通的方案：

- Apache-2.0，可商用、修改和再分发。
- 稳定 DOM 对象可以跨整条时间线存在，GSAP 只修改对象和相机状态，不需要切页。
- 动画时间轴可逐帧 seek；本机实际使用 BeginFrame 捕获 240 帧。
- CLI 原生支持 lint、check、snapshot、render，无需自己控制浏览器生命周期。
- HTML 是渲染源，也是 Studio/SDK 可查询和修改的对象树。
- 音频由渲染器识别、混音和封装，不靠页面实时播放。

推荐保留 Remotion 作为成熟保底，而不是同时维护两套正式模板。Revideo 保留为 Linux/Docker 复测候选；Motion Canvas 不进入生产主线。

## 2. 验收要求

| 要求 | 判定证据 |
|---|---|
| 连续画板 | 同一对象 ID 跨时间存在，并能平滑 `add/move/scale/highlight` |
| 相机 | 世界容器或原生 Camera 可平移、缩放，不切换整页 DOM/JSX |
| 固定口播 | 音频和字幕来自用户确认稿，视觉规划不能修改正文 |
| 数据驱动 | 对象和时间线来自 JSON/IR，不把每条视频写死为组件代码 |
| 无头渲染 | 有受支持的 CLI/API，可在无人操作时输出 MP4 |
| 音频同步 | 输出同时含视频轨和音频轨，时长、帧率可核验 |
| 人工微调 | 能基于稳定 ID 修改文字、位置、素材或时间，并保存修改 |
| 质量门禁 | 不只查黑帧，还要查低方差空画面、文字溢出和关键时刻截图 |
| 许可证 | 主链可合法商用，依赖许可证和版本可追踪 |

## 4. 同类本机实验结果

### 4.1 HyperFrames：通过，推荐主线

实验目录：`experiments/E01-render-engines/hyperframes-smoke/`

`canvas.json` 定义 3 个稳定对象和 9 个操作，`generate.mjs` 将其编译为同一个 3200x1400 世界画板。画面只对对象和 `#camera` 做 transform 动画，没有场景切页。

复现：

```powershell
cd experiments\E01-render-engines\hyperframes-smoke
node generate.mjs
npx.cmd -y hyperframes@0.7.59 lint --json
npx.cmd -y hyperframes@0.7.59 check --json --at-transitions --max-transition-samples 40
npx.cmd -y hyperframes@0.7.59 render --output ..\hyperframes-smoke.mp4 --workers 1 --crf 20 --strict
```

第一次 lint 找出并阻止了三个生产问题：

1. 音频没有 `id`，渲染会静音。
2. `left/top` tween 会按设备像素取整，慢动画会抖，应使用 `x/y` transform。
3. 中文系统字体未声明 `@font-face local(...)`，跨机字体会漂移。

修复后 lint 为 0 error、0 warning。实际渲染日志：

- 1920x1080、30 fps、240 帧、8.000 秒。
- H.264 视频 + AAC 48 kHz 双声道。
- 文件 767,594 bytes。
- 捕获阶段 15.39 秒，总渲染核心阶段约 16.58 秒。
- Windows 本机实际选择 BeginFrame、单 worker，并识别 RTX 4060 Ti。
- `blackdetect` 没有黑区间。
- 四个时刻的 contact sheet 显示对象新增、旧对象缩小保留和相机移动。

产物：

- `experiments/E01-render-engines/hyperframes-smoke.mp4`
- `experiments/E01-render-engines/hyperframes-smoke-contact.png`

人工编辑能力需要准确理解：HyperFrames Studio/SDK 已可预览、选择、查询、编辑 HTML/时间属性并保存，SDK 还有 patch/undo-redo 基础；但它还不是完整 Canva/剪映，任意元素的通用拖拽和关键帧 UI 仍在扩展。第一版产品仍应提供我们自己的“对象属性 + 时间预设”薄编辑层，而不是承诺完整自由设计器。

### 4.2 Motion Canvas：动画模型优秀，但不作为主线

实验目录：`experiments/E01-render-engines/motion-canvas-smoke/`

优点：

- 原生 `Camera` 节点，提供 `centerOn()`、`zoom()`、`reset()` 和路径跟随。
- scene graph、signals 和 generator 时间线非常适合长驻对象。
- TypeScript/Vite 构建通过，官方 FFmpeg 插件能输出音视频。
- MIT 许可证。

硬伤：

- 官方没有受支持的 headless CLI/API。2023 年提出的 issue #415 和 2025 年的 #1218 仍开放。
- 正式文档要求在编辑器点击 `RENDER`；源码虽支持 `?render` URL，但需要我们自行启动 Vite、启动 Chrome、等待完成并回收进程。
- Node Inspector 读取 signal 值并提供“GO TO SOURCE”，没有把属性修改写回源码；不是用户所需的通用可视化编辑器。
- 时间线主要用于播放、事件和音轨，不是可保存全部对象关键帧的设计时间线。

本机绕行验证确实生成了 `output/project.mp4`：1920x1080、30 fps、8.033 秒、H.264 + AAC 48 kHz。但过程先后遇到 Chrome profile 被 Vite 监听导致 `EBUSY`、音频 URL 路径解析失败。更重要的是，抽帧发现实验输出前半段为统一底色，虽然 `blackdetect` 通过。该现象不直接证明 Motion Canvas 引擎有 bug，但证明自建浏览器包装链没有足够的生命周期和语义 QA，当前产物不能验收。

结论：可借鉴它的 Camera 和 generator 抽象，不应把它作为本项目生产渲染主线。

### 4.3 Revideo：设计方向正确，Windows 本机暂未通过

实验目录：`experiments/E01-render-engines/revideo-smoke/`

Revideo 是从 Motion Canvas 演进出的 MIT 项目，正好补齐了 Motion Canvas 最大缺口：

- `renderVideo()` 原生 headless API。
- 多 worker 并行渲染。
- `variables` 参数化视频。
- React Player 可实时预览同一个项目。
- `<Video/>`、`<Audio/>` 与帧同步。
- CLI 可暴露 render endpoint。

它很适合“结构化 JSON -> TypeScript 场景适配器 -> 服务端渲染”。但 `0.11.0` 中没有 Motion Canvas 新版原生 `Camera` 类，需要用一个世界 `Node` 的反向 position/scale 自己实现相机，这只是薄适配，不是决定性问题。

本机证据：

```powershell
cd experiments\E01-render-engines\revideo-smoke
npm.cmd install
$env:DISABLE_TELEMETRY='true'
npm.cmd run render
```

- 安装成功，TypeScript 编译成功。
- 官方模板连续两次在 Puppeteer `page.goto()` 报 `Error: Navigating frame was detached`。
- 错误发生在 `@revideo/renderer` 创建 Vite server 后导航 renderer 页面阶段，尚未产出 MP4。
- 源码会强制追加 `--single-process`；这可能与 Windows/Chrome 150 有关，但本次没有足够证据把它定为唯一根因。

结论：不在当前 Windows 主线下注。若后续需要 Canvas scene graph 的高级路径动画，在 Linux Docker 做一次固定 Chrome 版本复测；通过后才可作为 HyperFrames 的备选，不能先把两套模板都维护起来。

### 4.4 Remotion：成熟保底，不是当前首选编辑模型

当前项目已有 `CanvasStyleDemo`，直接证明 Remotion 可以用一个常驻世界容器实现相机与长驻对象，不是 Remotion 本身只能分页。

现有产物 `renders/canvas-style-demo.mp4` 的本机 QA：

- 1280x720、30 fps、31.067 秒。
- H.264 + AAC 48 kHz 双声道。
- 5,491,060 bytes。
- `blackdetect` 没有黑区间。

优势是 CLI、渲染稳定性、React 生态和现有工程基础都成熟。缺点是自由画板的人工修改无法自然回写 JSX；Studio props 适合表单参数，不是 DOM 直接设计器。自定义许可证也会影响后续商业团队规模。

结论：保留为编码稳定性和迁移保底。如果 HyperFrames 在长片验证出现阻断级问题，再把同一 Canvas IR 适配到 Remotion，而不是现在双线开发。

## 6. 推荐的可编辑数据流

不能让 AI 每次直接重写完整 HTML，也不能让 Studio 修改在下一次生成时被覆盖。建议保留三层：

```text
plan/canvas.json       自动规划的对象、语义关系和初始布局
plan/timeline.json     add/move/scale/highlight/connect/camera 等操作
edits/overrides.json  用户基于稳定对象 ID 的修改补丁
        ↓
HyperFrames adapter   合并 IR + overrides，生成 HTML/CSS/GSAP
        ↓
Studio / SDK          预览、选择、调整；保存为新的 overrides
        ↓
lint/check/render/QA
```

`overrides.json` 至少支持：

- `text`：修改屏幕文案，不修改口播正文。
- `position/size/rotation/zIndex`：人工布局。
- `asset`：替换用户图片、SVG 或角色姿势。
- `timing`：调整开始、时长和动画预设。
- `camera`：移动视点和 zoom。
- `hidden/locked`：隐藏或锁定对象。

每个 HTML 对象必须同时有稳定、可读的 `id`；媒体元素也必须有 `id`，否则 HyperFrames 渲染器无法可靠发现音频。动画只使用 transform/opacity/clip/path 等稳定属性，避免 `left/top/width/height` 慢速 tween。

## 7. 组合方式建议

应该组装，而不是重写，但“组装”不等于同时运行四个视频引擎。建议边界如下：

| 能力 | 选用积木 | 本项目只写什么 |
|---|---|---|
| 连续时间轴与无头渲染 | HyperFrames + GSAP | Canvas IR 到 HTML/GSAP 的薄适配器 |
| HTML 文字/卡片/代码 | 浏览器原生 HTML/CSS | 主题 token 和可复用组件 |
| 流程图和架构图 | Mermaid/D2/Graphviz/ELK 评测胜者 | SVG 元素 ID 注入与动画映射 |
| 人工画板修改 | HyperFrames SDK/Studio + 画板编辑器评测胜者 | 稳定 ID、override patch 和属性面板 |
| 音频和字幕 | 已审稿稿件 + TTS 时间戳 + HyperFrames audio | 字幕数据适配和术语词典 |
| 编码和检查 | HyperFrames/FFmpeg/FFprobe | QA 编排与报告 |
| 保底渲染 | Remotion | 只有主引擎出现阻断时才实现第二适配器 |

不建议将 Motion Canvas 或 Revideo 嵌在 HyperFrames 内再捕获。双时间轴嵌套会增加 seek、音频和字体问题，失去当前选型带来的简化。

## 8. 下一步实施门禁

不再扩大渲染引擎候选池，直接做以下最小完整链：

1. 定义 `canvas.schema.json`、`timeline.schema.json` 和 `overrides.schema.json`。
2. 把本次 `generate.mjs` 升级为正式 HyperFrames adapter，禁止任意模型代码进入渲染层。
3. 用用户确认的 45-60 秒稿件生成 12-20 个稳定对象和连续相机时间线。
4. 提供对象文字、位置、素材、动画预设和时间的最小人工编辑入口。
5. 用户修改后只更新 `overrides.json`，重新生成并渲染。
6. QA 同时执行轨道/时长、blackdetect、低方差空画面、关键时刻截图、文字溢出和音频响度检查。
7. 将 HyperFrames 固定为 `0.7.59`；升级必须先重跑此 E01 基准。

只有出现以下阻断，才启动 Remotion 备选适配：同一输入无法确定性 seek、长音频持续错位、Studio/SDK 无法保存所需修改、或 3-5 分钟成片渲染持续失败。视觉风格不好不属于换引擎理由，应在组件、布局、素材和动画规划层解决。
