# 端到端开源视频工作流调研

> 调研日期：2026-07-16  
> 目标：用户提供已经确认的口播稿，系统只做视觉规划、素材准备、连续单画板动画、配音/字幕、可视化人工微调和确定性 MP4 渲染。  
> 结论依据：GitHub API 元数据、指定提交的 README / License / Schema / 渲染入口，以及本机 `vendor/hyperframes` 源码。Star 只作为项目热度快照，不作为能力证明。

## 1. 结论先行

推荐主线不是把多个完整系统硬接在一起，而是选择一个同时覆盖“动画源码、可视化编辑、时间线和渲染”的核心，再把其他项目中成熟的独立能力接进来。

**当前最优主线：HyperFrames + 自有的薄编排层。**

- HyperFrames 负责 HTML/CSS/SVG/GSAP 画板、可视化 Studio、关键帧、音频时间线、预览、检查和 MP4 渲染。
- 自有薄编排层负责锁定口播原文、语义切分、视觉计划、资产清单、稳定对象 ID、连续画板布局和局部重算。
- Edge TTS 先负责中文配音，真实音频时长与词边界驱动画面和字幕。
- 图表/图示工具只输出 SVG/HTML 资产，作为画板对象进入 HyperFrames，不直接生成整条视频。
- FFmpeg/ffprobe 负责最终音视频检查；可借鉴 OpenMontage 和 ResearchStudio 的 QA 关卡，但不需要引入它们的整套运行时。
- PPT Master 作为可选的“另交一份可编辑 PPTX”或复杂信息页设计工具，不作为视频主时间线。

这条路线的关键原因是：HyperFrames 已经有可持久化的画面编辑和 GSAP 关键帧编辑，不再需要先接 tldraw/Excalidraw，再自己维护编辑器文档与渲染文档的双向转换。

### 1.1 需要对 HyperFrames 默认工作流做的调整

HyperFrames 的 `faceless-explainer` 已支持把用户脚本保存为 `user_script.txt`，并明确询问 `verbatim` 或 `restructure`。但它默认仍按多个 frame/sub-composition 组织内容，容易再次做出分页感。

正式工作流不能原样调用它的逐 frame 组装步骤，而应复用其中的设计系统、音频、字幕、媒体账本、检查与渲染能力，然后增加一个很薄的“连续画板编译器”：
```text
approved narration
  -> visual-plan.json
  -> board objects with stable ids
  -> literal GSAP keyframes in one long-lived composition
  -> HyperFrames Studio manual edits
  -> lint/check/snapshot/render
```

根画布、世界画板、字幕层、人物锚点始终存在；镜头和画板对象改变状态，而不是切换页面。

## 4. 指定项目逐项核验

### 4.1 HyperFrames：采用为主引擎

真实能力不只停留在“HTML 转 MP4”。本机源码已经包含：

- `npx hyperframes preview/lint/check/snapshot/render` 的确定性制作链。
- HTML、CSS、SVG、媒体与暂停的 GSAP timeline；渲染器逐帧 seek，而不是让动画按墙钟自行播放。
- Studio 直接选择 DOM 元素，修改文字、位置、尺寸、颜色、渐变、图片、透明度、圆角、排版等，并把改动回写源 HTML。
- 时间线拖动与裁切会回写 `data-start`、`data-duration`、`data-track-index` 和 `z-index`。
- Studio 自动识别 `.to()` / `.from()` / `.fromTo()` 关键帧，在设计面板修改位移、缩放、透明度、时长和 easing。
- 可将直线运动转为 MotionPath 弧线；可在播放时拖动物体录制手势，自动简化成 5-15 个 GSAP 关键帧。
- 变量面板、素材列表、嵌套 composition、字幕、音频、渲染任务和源代码编辑。
- `faceless-explainer` 明确允许用户脚本选择 verbatim；原稿可不被模型改写。

关键源码证据：

- [Studio 手工 DOM 编辑](https://github.com/heygen-com/hyperframes/blob/10b3351974766b0effd99dce6be356787c6af89c/docs/contributing/studio-manual-dom-editing.mdx)
- [Studio 时间线编辑](https://github.com/heygen-com/hyperframes/blob/10b3351974766b0effd99dce6be356787c6af89c/docs/guides/timeline-editing.mdx)
- [关键帧、弧线与手势录制](https://github.com/heygen-com/hyperframes/blob/10b3351974766b0effd99dce6be356787c6af89c/docs/guides/keyframes.mdx)
- [faceless-explainer 工作流](https://github.com/heygen-com/hyperframes/blob/10b3351974766b0effd99dce6be356787c6af89c/skills/faceless-explainer/SKILL.md)
- [Apache-2.0 License](https://github.com/heygen-com/hyperframes/blob/10b3351974766b0effd99dce6be356787c6af89c/LICENSE)

限制也必须保留：

- 默认 faceless 工作流是一帧/一段 HTML 的故事板，不天然等于持续画板。
- Studio 对自由 DOM 的直接编辑是保守的。绝对定位、稳定 ID、像素几何最可靠；复杂 flex/grid 或 transform 驱动布局可能需要先 `Make movable`。
- 通用运动 clip 能移动和右裁切，但暂不能像媒体一样真正从动画内部做左裁切。
- helper/loop 生成的 GSAP tween 可能需在 Studio 中 `Unroll to edit`；为人工微调，应优先输出显式 literal tween。
- npm 要求 Node >= 22；本机 clone 对应 `0.7.58` 附近，npm latest 已是 `0.7.59`，正式实验前需同步版本并重新跑 Windows 渲染检查。

**采用方式：** 不 fork 渲染器核心。用它公开的 HTML/Studio/CLI 合同，在项目侧增加连续画板 schema 与生成适配器。

### 4.2 PPT Master：采用为可编辑 PPT / 视觉资产支线

PPT Master 的强项是真正原生可编辑的 PPTX，而不是每页一张图：

- PDF、DOCX、网页或文本进入 agent 工作流。
- 每页设计先落为 SVG，最终转换成 DrawingML 文本、形状、图表和表格。
- `animations.json` 可按顶层 `<g id>` 定义入场效果、顺序、延迟、时长和 trigger。
- speaker notes 可通过 Edge TTS、ElevenLabs、MiniMax、Qwen 或 CosyVoice 生成逐页音频并嵌入 PPTX。
- 生成旁白后，按音频时长写页面自动推进；最终 MP4 仍由桌面 PowerPoint/Keynote 导出。
- 浏览器预览支持文本/SVG 属性编辑和注释，最终还可在 PowerPoint 逐元素修改。

证据：

- [音频旁白与视频导出](https://github.com/hugohe3/ppt-master/blob/4c7e963520029ea45b6417a23d03e25537a921da/docs/audio-narration.md)
- [转场与页内动画](https://github.com/hugohe3/ppt-master/blob/4c7e963520029ea45b6417a23d03e25537a921da/docs/zh/animations.md)
- [PPT Master Skill](https://github.com/hugohe3/ppt-master/blob/4c7e963520029ea45b6417a23d03e25537a921da/skills/ppt-master/SKILL.md)

不作为主引擎的原因：

- 页面是基本单位，无法自然表达无限画板上对象跨章节持续存在。
- 视频自动导出依赖 PowerPoint GUI；项目本身只准备 video-ready PPTX。
- narrated/video export 没有对象级 click timing，只能使用 `after-previous` / `with-previous`。
- PowerPoint、WPS、Keynote、LibreOffice 对动画语义的实现并不完全相同。
- 默认 agent 会设计并撰写 notes；必须增加“用户口播原文只读”的适配约束。

可直接复用的部分：SVG 资产生产规范、语义 `<g id>`、动画 sidecar 思路、资料转 Markdown、图像 provider、Edge/云 TTS 接口，以及可选 PPTX 交付。

### 4.3 OpenMontage：借鉴工作流合同，不直接成为产品依赖

OpenMontage 的真实价值是生产治理，而不是一个开箱即用的连续画板编辑器：

- `pipeline_defs/animated-explainer.yaml` 定义 research、proposal、script、scene plan、assets、edit、compose、publish 和人工审批点。
- 有 `script.json`、`scene_plan.json`、`asset_manifest.json`、`edit_decisions.json`、render report、final review 等 JSON Schema。
- 有多 provider 选择、成本日志、参考视频分析、资产工具、TTS、字幕、Remotion/HyperFrames/FFmpeg runtime 选择及渲染后 QA。
- 可在 `composition_mode=atelier` 时使用项目本地手写 composition，能力上可以制作非模板画面。

但它不是本需求的直接答案：

- Script Director 的职责明确是“从头写旁白”，不是消费锁定口播。
- `edit_decisions` 的主模型仍是 cuts、overlays、transitions，默认画面是 scene/cut 语言。
- Remotion `Explainer` 是 text card、chart、image/video、comparison 等场景组件集合，不是常驻世界画板。
- Backlot README 明确说明它是 **read-only local board**；能看脚本、storyboard、成本和审批状态，不能拖动画面对象或关键帧。
- AGPL-3.0 对以后封装成网络服务有明显合规义务；在已有 Apache/MIT 选择时，没有必要引入这项风险。

证据：

- [Animated Explainer Pipeline](https://github.com/calesthio/OpenMontage/blob/f8d94632ea9bd0057da31904acca1cefecf005dd/pipeline_defs/animated-explainer.yaml)
- [Script Schema](https://github.com/calesthio/OpenMontage/blob/f8d94632ea9bd0057da31904acca1cefecf005dd/schemas/artifacts/script.schema.json)
- [Edit Decisions Schema](https://github.com/calesthio/OpenMontage/blob/f8d94632ea9bd0057da31904acca1cefecf005dd/schemas/artifacts/edit_decisions.schema.json)
- [Backlot README](https://github.com/calesthio/OpenMontage/blob/f8d94632ea9bd0057da31904acca1cefecf005dd/backlot/README.md)

可借鉴但不复制 AGPL 源码的部分：阶段门禁、provider receipt、成本账本、资产 manifest、渲染 runtime 锁定、ffprobe/抽帧/转写复核和失败恢复策略。

### 4.4 Microsoft ResearchStudio / Paper2Video：借鉴工具链，不用视觉模型

微软版本的 Paper2Video 是一个真实可运行的组合器，且它自己也明确写道“orchestrator，不替代 deck、TTS 或 FFmpeg”：

- 优先使用 `paper2assets` 的论文结构化资产。
- 调用外部 PPT Master 生成可编辑 PPTX 与 speaker notes。
- 生成逐页 Edge TTS 音频、SRT/VTT、timeline、visual cues 和严格 QA 报告。
- 输出 `video.pptx`、带字幕 `video.mp4`、无字幕 `video_no_subtitles.mp4`。
- 能从已有 PPTX + speaker notes 路径开始，适合注入人工确认稿。

但其视频渲染实现会把 `svg_final` 或 PPTX 页面光栅化成 PNG，将每张静态页面与对应 MP3 组成片段，再用 FFmpeg concat；所谓 `spotlight_laser` 是在静态页上叠加聚光灯/激光点。它不会播放 PPT 原生动画，更不是连续画板。

证据：

- [Paper2Video README](https://github.com/microsoft/ResearchStudio/blob/61277686638adb87298a26cc7621cd7387723fb4/ResearchStudio-Reel/skills/paper2video/README.md)
- [Paper2Video Skill](https://github.com/microsoft/ResearchStudio/blob/61277686638adb87298a26cc7621cd7387723fb4/ResearchStudio-Reel/skills/paper2video/SKILL.md)
- [实际渲染脚本](https://github.com/microsoft/ResearchStudio/blob/61277686638adb87298a26cc7621cd7387723fb4/ResearchStudio-Reel/skills/paper2video/scripts/render_video.py)

可复用：PPTX/音频数量和顺序校验、真实时长规划、字幕 sidecar、timeline 输出、视觉 cue 契约、包结构和严格 QA。视觉渲染本身不采用。

### 4.5 showlab/Paper2Video：淘汰

这是另一套项目，不能与 Microsoft ResearchStudio-Reel 的 Paper2Video 混为一谈。它面向论文演讲数字人：输入 LaTeX 论文工程、人物参考图和参考音频，生成 slides、字幕、光标、声音和 Hallo2 talking head。

README 推荐最低 NVIDIA A6000 48 GB，并示例使用多块 GPU；依赖 Conda、Tectonic、LLM/VLM API，以及可选的 Hallo2 独立环境。它不以用户锁定口播、连续画板或轻量人工编辑为目标，因此不进入候选链。

证据：[中文 README](https://github.com/showlab/Paper2Video/blob/47beb503e24218f8f8b3075f5d2bed7844d199b4/README-CN.md)。

### 4.6 Presenton：可选页面/PPT 编辑器，不做视频核心

Presenton 是成熟的自托管演示文稿应用：

- Docker、Electron 和 API 路径齐全，支持 OpenAI-compatible endpoint、Ollama、LM Studio 等。
- API 可以直接传 `content`，也能传 `slides_markdown` 跳过自动内容生成。
- 有完整 slide UI、元素/组件增删、移动、缩放、分组、层级、图表、图片、speaker note，以及聊天式精确编辑工具。
- 可导出可编辑 PPTX 或 PDF。

它的边界也很明确：没有视频导出、TTS、字幕或动画时间线；数据模型是 1280x720 slide，而不是世界画板。把整个 Presenton 嵌进来再转成视频，会重新引入 slide -> video 的大适配层，得不偿失。

证据：

- [Presenton README/API](https://github.com/presenton/presenton/blob/a6c96a7e7cbd9a9f54fdaee6b2cc84f3e737b1f5/README.md)
- [聊天编辑规则](https://github.com/presenton/presenton/blob/a6c96a7e7cbd9a9f54fdaee6b2cc84f3e737b1f5/servers/fastapi/services/chat/prompts.py)
- [Apache-2.0 License](https://github.com/presenton/presenton/blob/a6c96a7e7cbd9a9f54fdaee6b2cc84f3e737b1f5/LICENSE)

建议只在未来需要“先人工做一页复杂信息页，再作为 SVG/图片资产带入画板”或需要额外交付 PPTX 时评估；第一版不部署。

### 4.7 MoneyPrinterTurbo：保留素材/TTS参考，不采用画面生成方式

项目确实支持自定义 `video_script`。`generate_script()` 只有在该字段为空时才调用 LLM，因此可以保证输入稿不被重新生成。它还包含：

- Edge TTS、Azure、SiliconFlow、Gemini、MiMo、ElevenLabs、Chatterbox。
- Edge 边界或 Whisper 字幕，中文字体与字幕样式。
- Pexels、Pixabay、Coverr、本地素材、BGM、横竖屏、API/CLI/WebUI。
- 按稿件匹配素材、片段时长、若干入场/出场/缩放转场。

但 `VideoParams` 与 `video.py` 证明其画面模型是“视频素材切成若干 clip，循环到覆盖音频，再 MoviePy/FFmpeg 合成”。WebUI 可以改稿件、素材和参数，但不产生能手工拖动物件/关键帧的工程。

证据：

- [输入参数 Schema](https://github.com/harry0703/MoneyPrinterTurbo/blob/819531e7fb383605ec8a0f691a3980163868b0d1/app/models/schema.py)
- [任务编排](https://github.com/harry0703/MoneyPrinterTurbo/blob/819531e7fb383605ec8a0f691a3980163868b0d1/app/services/task.py)
- [视频片段合成](https://github.com/harry0703/MoneyPrinterTurbo/blob/819531e7fb383605ec8a0f691a3980163868b0d1/app/services/video.py)

结论：它适合库存素材型短视频，不适合老师在画板上持续讲解。Edge TTS 当前已有更轻的直接接入，不必为了 TTS 引入整个项目。

## 5. 额外发现的项目

### 5.1 Revideo：最合理的备选动画引擎

[Revideo](https://github.com/midrender/revideo) 是 Motion Canvas 思路的活跃分支/演进项目，MIT 许可，支持 TypeScript generator scene、矢量节点、SVG、代码、音视频、浏览器 Player、headless `renderVideo()` 和并行渲染。它非常适合长存对象、连续状态和相机动画。

问题是它没有 HyperFrames Studio 这种面向最终用户、能把拖动和关键帧修改可靠回写源码的完整编辑层。它更适合开发者编写动画，不适合当前“自动生成后用户自己微调”的优先级。因此作为 HyperFrames 渲染/稳定性实验失败时的 B 方案，不作为并行主线。

### 5.2 Twick / OpenVideo：编辑能力强，但许可证不优

- [Twick](https://github.com/ncounterspecialist/twick) 有 Fabric.js canvas、timeline、Studio、字幕、浏览器/服务端渲染和 JSON 项目，技术能力很匹配 NLE 编辑。但它使用自定义 Sustainable Use License：托管 SaaS、竞争产品和“substantial revenue”需要商业协议，不是标准开源许可证。
- [OpenVideo](https://openvideo.dev) 曾公开 PixiJS/WebCodecs 画布、轨道、拖拽、缩放、旋转和本地 MP4；其历史免费许可只覆盖个人、非营利或不超过 3 人的公司，更大组织需要 Company License。原公开仓库 `openvideodev/openvideo` 在 2026-07-16 复查时已返回 404，当前源码入口和可复用版本不可核验，更不能作为基础依赖。

两者的工程模型偏通用 NLE，且许可证明显不如 Apache-2.0 的 HyperFrames，暂不采用。

### 5.3 OpenCut：未来再看，当前重写未完成

[OpenCut](https://github.com/OpenCut-app/OpenCut) 是 MIT，但当前 README 明确写着正在从头重写，Editor API、插件、MCP、headless 和 scripting tab 都是“What's coming”，并建议今天使用 classic。不能把路线建立在尚未落地的 headless/API 能力上。

### 5.4 pyJianYingDraft：只做可选下游草稿

它能生成剪映草稿、文本/音视频/贴纸轨道、关键帧、动画、转场和模板替换，确实能给用户一个熟悉的人工修改入口。但：

- README 明确批量导出只支持剪映 6 及以下；剪映 7+ 隐藏控件。
- 导出依赖 Windows `uiautomation`、前台窗口和鼠标点击，不适合作为确定性无人值守主链。
- 新版草稿内部格式兼容性持续存在风险。
- 它擅长 NLE 轨道，不会自动创造连续 HTML/SVG 知识画板。

因此可以在 MP4 已生成后，额外导出一个剪映草稿用于加贴纸、BGM 或发布前微调，但不能成为主渲染器。

### 5.5 short-video-maker 与小型 Remotion 模板：淘汰

- `gyoridavid/short-video-maker` 是 Kokoro 英文 TTS + Whisper + Pexels + Remotion 的背景素材短视频服务；README 明确当前只支持英文声音、背景只来自 Pexels，Windows npm 路径不受支持，且代码最后 push 早于其他候选约一年。
- `eyecool7/animated-infographic-generator` 虽然名称高度匹配，但 API 快照只有 2 Star、单次初始提交级体量且无 License，不能直接复用到生产系统。
- `meimouren/make-video-template` 是很小的中文 Remotion 模板且无 License，适合参考，不适合成为基础依赖。

## 6. 推荐的组装架构

### 6.1 不可变口播层

```text
source/narration.approved.md
source/pronunciation.json
plan/narration.json
plan/narration.lock.json
```

- `narration.approved.md` 是唯一口播事实源。
- `narration.lock.json` 保存 SHA-256、字符数、段落边界和生成时间。
- AI 只能生成视觉字段，任何输出中的 narration 拼接后必须与原文规范化结果逐字一致；不一致直接失败。
- TTS 只读取锁定稿，不读取视觉计划里的转述文字。

### 6.2 视觉计划与资产层

```text
plan/visual-plan.json
assets/asset-manifest.json
assets/svg/
assets/images/
assets/icons/
audio/narration.mp3
captions/words.json
```

`visual-plan.json` 只描述教学视觉：对象、父子关系、空间区块、强调点、连线和相机意图。图表/流程图工具、AI 图片或用户图片都先写入 `asset-manifest.json`，带来源、许可证、prompt/hash 和尺寸。

### 6.3 单画板 HyperFrames 工程

```text
canvas/
  index.html
  board.generated.json
  theme.json
  overrides.user.json
  assets/
  renders/
```

建议 HTML 结构：

```html
<div id="root" data-composition-id="lesson" data-duration="...">
  <div id="camera">
    <div id="world-board">
      <section id="obj-rag-definition">...</section>
      <section id="obj-retrieval-flow">...</section>
      <svg id="obj-vector-path">...</svg>
    </div>
  </div>
  <div id="captions">...</div>
</div>
```

实现规则：

- `root`、背景、人物和字幕永不切换。
- 画板对象使用稳定业务 ID，不用数组下标。
- 旧对象通过 move/scale/opacity 重排，不把整个 scene 卸载。
- 相机只是 `camera` 的 translate/scale keyframes。
- 首版只输出 Studio 最容易回写的绝对定位与像素尺寸。
- 关键动画输出显式 `tl.fromTo()` / `tl.to()`，避免动态 helper；保证 Studio 可见、可改、可撤销。
- 每个对象同时保留 `data-source-segment-id`，从画面可追溯到口播段落。
- 字幕和旁白以真实 TTS timing 为准；画面关键帧在音频生成后定时。

### 6.4 人工微调流程

```text
npx hyperframes preview
  -> 选中对象改文字/颜色/图片/位置/尺寸
  -> 时间线改出现和结束时间
  -> 关键帧 diamond 改时刻/属性/easing
  -> 必要时录制拖动手势或改弧线路径
  -> 源 HTML/GSAP 持久化
  -> snapshot/check
  -> render
```

第一版不要另外开发一套编辑器 UI。直接把 HyperFrames Studio 作为工程编辑器，外层只做一个项目列表、生成按钮和“打开编辑器”入口。等真实使用证明 Studio 哪些能力不足，再决定是否嵌入 `@hyperframes/studio` 做定制面板。

### 6.5 保留手工修改的策略

自动生成后，`index.html` 就成为本次视频的可编辑发布源，不能每次把整份文件重新生成覆盖。

- 初次生成写 `board.generated.json` 和 HTML。
- Studio/用户修改后记录项目版本或 Git diff，并将用户明确覆盖项同步到 `overrides.user.json`。
- “改一张图/一句屏幕文字/一个动画”按稳定对象 ID 做局部 patch。
- 只有用户选择“重新规划本章节”时才重建该章节对象；其他 DOM 和 GSAP 不动。
- 用户锁定的对象增加 `data-user-locked="true"`，后续 agent 不得覆盖。

## 7. 哪些模块直接复用，哪些不要复用

### 直接复用

| 能力 | 来源 | 复用方式 |
|---|---|---|
| HTML/SVG/GSAP 渲染 | HyperFrames | npm/CLI 直接依赖，不 fork core |
| 可视化 DOM、时间线、关键帧编辑 | HyperFrames Studio | 第一版直接运行 `preview`；后续可嵌入公开包 |
| faceless 设计预设、字幕、媒体账本、TTS 流程 | HyperFrames skills | 复用步骤和脚本，但替换逐-frame assembler |
| Edge TTS | Edge TTS/现有本项目链 | 继续使用，先跑通中文流程 |
| PPTX 额外交付 | PPT Master | 独立可选任务，不参与主时间线 |
| 严格媒体 QA 思路 | HyperFrames + ResearchStudio + OpenMontage | 用各自 CLI/脚本或薄适配组合，保存报告 |
| 最终编解码/探测 | FFmpeg/ffprobe | 直接调用标准工具 |

### 不要直接复用

| 内容 | 原因 |
|---|---|
| OpenMontage 全仓作为产品依赖 | AGPL；默认脚本和 scene/cut 模型不匹配；Backlot 只读 |
| ResearchStudio 的静态 slide concat 渲染 | 必然回到 PPT 翻页感 |
| MoneyPrinterTurbo 的库存视频拼接主链 | 抽象知识语义弱，不能形成画板对象身份 |
| Presenton 整套编辑器 | slide 模型；与 HyperFrames Studio 功能重叠；接入面太重 |
| Twick/OpenVideo | 自定义商业许可证，且偏通用 NLE |
| 剪映 GUI 自动导出 | 不确定性高、版本脆弱、占用前台鼠标 |
| 低 Star 且无 License 的 Remotion 模板 | 无法形成可靠依赖或合法复用基础 |

## 8. 部署前置条件

主线第一版不需要 GPU。需要：

1. Node.js >= 22；HyperFrames npm 当前 latest 为 `0.7.59`。
2. FFmpeg/ffprobe 在 PATH，或明确配置可执行文件。
3. Chrome/HyperFrames 管理的 headless shell；Windows 上跑一次 `doctor` 和真实渲染。
4. Edge TTS 需要联网；正式生产前准备一个可替换的云 TTS provider。
5. 当前 OpenAI-compatible LLM endpoint 只用于视觉规划，不允许改写锁定稿。
6. 中文字体必须作为项目资产冻结，不能依赖某台电脑恰好已安装。
7. 图片、图标、BGM 和用户素材写入来源/许可证 manifest。
8. 只有启用 PPT 支线时才需要 Microsoft PowerPoint；主视频链不应依赖 Office。
9. 只有启用剪映支线时才需要兼容版本剪映；它不是主链前置条件。

## 9. 第一轮本机实验建议

不要先做 3-5 分钟完整产品，先用一份 30-45 秒已经确认的中文口播完成以下闭环：

1. 将本机 HyperFrames 与 npm `0.7.59` 对齐，运行 `doctor`。
2. 创建一个只有一个 root composition 的 16:9 连续画板工程。
3. 画板至少包含 8 个稳定对象：标题、人物/锚点、3 个流程节点、2 条连接线、结论卡。
4. 用真实 Edge TTS 音频安排 add/move/scale/highlight/connect/camera 动画。
5. 在 Studio 中人工完成四类修改：改文字、拖位置、改关键帧时刻、替换图片。
6. 关闭 Studio 再打开，确认修改仍在；重新渲染确认与 preview 一致。
7. 修改 `visual-plan.json` 中一个未锁定对象，验证不会覆盖其他人工修改。
8. 执行 lint、check、关键时间 snapshot、ffprobe、blackdetect、抽帧和音频/稿件完整性检查。
9. 与同稿 Revideo 小样比较一次，仅用于验证 HyperFrames 的渲染/动画限制，不同时维护两套正式实现。

通过标准不是“能生成 MP4”，而是：整段没有换页感、对象身份连续、人工修改能持久化、口播逐字不变、局部重做不覆盖其他内容。

## 10. 最终推荐排序

1. **HyperFrames 单 composition 连续画板 + Studio + 自有薄编排层**：最优。
2. **Revideo 连续画板 + 另接编辑器**：只有 HyperFrames 实测出现不可接受限制时启用。
3. **PPT Master + PowerPoint**：需要可编辑 PPTX 的独立交付路线，不是目标视频风格主线。
4. **Presenton + 外部视频链**：适合幻灯片产品，不建议投入本目标。
5. **OpenMontage 全链**：作为研究和治理范本；因 AGPL、只读看板和 scene/cut 模型不直接采用。
6. **MoneyPrinterTurbo / short-video-maker**：库存素材型短视频，不适合连续知识画板。
7. **ResearchStudio / 两个 Paper2Video**：仅在学术 PPT/数字人场景使用。

这次调研后的核心变化是：不再优先自研 Motion Canvas 画板编辑器，也不再优先做 tldraw 到渲染器的双向适配。先充分利用 HyperFrames 已经存在的 Studio 与关键帧能力，只开发它缺少的“已审稿口播 -> 连续画板对象/关键帧”编排层，工程量和后续维护成本最低。
