## 3. 叙事目标

本视频告诉关注 AI 和工程能力的中文观众：

> AI 生成和低代码表面很廉价，真正稀缺的是理解、判断、维护和负责；只有把 Demo 变成可维护系统，才是产品能力。

观众看完需要记住三件事：

1. 会拖拽节点、会写提示词、会生成一个 Agent，不等于理解系统。
2. 真正的产品要面对异常、并发、成本、权限、数据、日志、测试、回滚和维护。
3. 创建变得廉价后，理解、判断、维护、负责才是高价值能力。

### 叙事顺序

警醒 → 误解的表面 → 五个原因 → 逐层拆开系统 → 可维护产品的检查清单 → 从玩具到基础设施 → 学习路线 → 结论锁定。

不把它做成 14 个互不相干的页面。14 个章节是相机停靠点，所有对象都位于同一张超大画板上；上一章对象继续保留，进入下一章后降对比度或退到背景。

## 4. A6 视觉规范（硬约束）

基础风格只使用 handdrawn-workflow-tutorial，不混用另外两套完整风格。

### 视觉令牌

- 画布：暖白 #FBFAF4，极弱纸纹和暖色暗角。
- 线条：近黑墨线 #151515，2–4px，圆端点。
- 当前结论/确认/执行：胭脂红 #D81E45，只保留一个主红焦点。
- 被提取的信息：浅青 #DDF4F5。
- 字体：大标题和关键词优先，信息卡正文不超过 8 个汉字；禁止小字号代码墙。
- 版式：单一连续画板，左到右或斜向巡讲；不使用分屏硬切。

### 语义组件

- sketch-browser：代表公开的表面、社群、工具入口或可见按钮。
- info-card：把口播中的一个概念提取成浅青/白卡；同屏最多 4 张。
- step-rail：把五个原因或 Agent 检查项组织成一条黑色手绘流程线；当前节点最清楚。
- step-paper：承载学习路线、检查清单和可复制步骤；同屏 1–3 张。
- ink-arrow：表示因果、传递、揭示；同时最多 2 条活跃箭头。
- action-pill：胭脂红白字胶囊；同屏只允许 1 个主标签。
- tool-window：简化的工具/系统窗口；同屏最多 1 个。
- pin-sticker：图钉或胶带只做轻微定位；同屏最多 4 个。

### 动效硬规则

- 一句一动：新名词先生成对象，解释关系才画线，说到“下一步/送进/确认”才移动或锁定。
- 每个信息点至少一个可解释变化：生成、拆分、连接、传递、移动、聚合、状态切换、镜头推进或关系高亮。
- 相机是画面流动的主动力；用一个可 seek 的 world 变换巡讲各站点。
- 线条用 SVG path draw；卡片用轻拍落位；节点按阅读顺序点亮；纸张沿箭头传递。
- 章节之间用持续相机运动、墨线或纸条交接；不使用黑场、闪白、整页滑页、glitch、粒子或无意义转场。
- 不提前展示后句的技术名词。任何屏幕摘要必须带 source range 和类型。
- 最后一个关键动作必须在 274.394667 秒前完成，终帧至少保留 2.5 秒可读。

### 明确禁止

真实录屏复刻、密集工具栏、长篇代码、满屏撕纸、儿童插画、多个红色重点、大幅弹跳、旋转飞入、镜头抖动、霓虹、全屏闪白、无意义鼠标移动、把每个步骤做成单独页面。

## 5. 连续画板世界

画板不是一组幻灯片，而是一张预先放置站点的宽画布。相机从左向右巡讲，局部停靠时只改变当前站点的状态。

    [警醒与观众]──墨线──[表面很简单]──[五个原因轨道]
                                          ├─ 01 复杂性被隐藏
                                          ├─ 02 原型不等于产品
                                          ├─ 03 只展示结果不展示维护
                                          ├─ 04 弯道超车的误解
                                          └─ 05 Agent 的工程问题清单
                             ──墨线──[玩具 → 工具 → 产品 → 基础设施]
                                          ──[学习路线]──[理解 / 判断 / 维护 / 负责]

## 6. 节奏与相机计划

节奏命名：慢起警醒 → 中速建立误解 → 5 个连续中速站点 → 快速检查清单 → 放慢转化 → 最后 2.5 秒稳定定格。

- 0–19s：首句不从空白开始；先让暖白画板和一个红色下划线出现，再建立警醒。
- 19–52s：相机连续向右移动，表面卡片逐渐露出背后的空层。
- 52–57s：短暂停留，五节点轨道一次建立，明确“接下来逐个拆”。
- 57–214s：每个原因站点约 25–31 秒；站点内部用 3–6 个小动作，不清空画面。
- 214–249s：相机速度放慢，四级对象沿同一条线完成转化，学习路线纸张接入。
- 249–274s：减少新对象，保留累计状态；最后一句只完成一次红色锁定动作并保持。

推荐可复用积木：

- blueprint：spatial-pan-stations（单一 oversized canvas + 虚拟相机）。
- motion rule：viewport-change（world 相机巡讲）。
- motion rule：svg-path-draw（手绘引线、箭头、圈选）。
- motion rule：css-marker-patterns（荧光笔/墨迹标记）。
- 实现约束：一个 paused、seek-safe 的 GSAP timeline；所有动画都属于该时间线。

## 9. 屏幕文字与字幕规则

### 类型

- exact-source：直接来自口播的短词或短句，例如“第一”“五个原因”“Magic”“Engineering”“不能”。
- approved-summary：由口播直接归纳、等待本次审核批准，例如“表面入口”“一次跑通 ≠ 长期稳定”“可维护 Agent 检查表”。
- generated-summary：当前只作为候选，不得进入成片；例如“从 Demo 到产品”“学习路线”。

默认制作规则：在你没有逐条批准摘要前，只允许 exact-source、原文数字/术语和逐字字幕。generated-summary 可替换为纯图形关系，例如叉号、空心节点、箭头或位置对照。

### 字幕

- 底部安全区保留一条暖白/半透明纸条，不做黑色 HUD。
- 字幕跟随 sentence cue，按自然停顿分段；不把 274 秒全文同时铺在画面。
- 每次最多两行；重点词用墨线或浅青底，不用多个红色标签。
- 字幕和画面对象共用 source range；画面不能先显示后句的名词。
