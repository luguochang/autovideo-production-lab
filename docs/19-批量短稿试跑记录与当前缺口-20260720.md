## 2. 本轮发现并记录的失败

### 2.1 适用性报告不能直接作为 evidence

第一次执行口播化时把 `material-suitability.json` 误传给 `--evidence`，命令拒绝并报告 schema 不匹配。这个行为是正确的门禁：适用性、证据台账和口播草稿必须是三个独立产物。

### 2.2 自动口播化受到外部服务限制

使用 `content:rewrite --run-codex` 时，Codex 子进程因外部服务 `429 Too Many Requests` 重试耗尽而失败。没有因此跳过 schema 校验；本轮改用明确的 `--draft` 入口提交绑定当前来源和证据的草稿。

待补能力：在本地或可重试的生成服务中实现受控的口播化执行，并保留失败重试、超时和人工草稿回退记录。

## 4. 与成熟批量交付的剩余缺口

- 动效配方仍需人工完成九项探针审片；E06、E15、E16、E17 两类和 E18 均保持 `candidate`。
- 配方晋级为模板需要不同项目的 hash-bound 人工批准，不能由 strict check 自动完成。
- SFX 目前已有本地资产和候选计划，但真实项目仍需逐项听审后才能进入时间线。
- 公开发布仍需要 CosyVoice 声音权利、人物/字体/图片素材权利、人工听审、Studio 全片审片和字幕/OCR/语义 QA。
- 批量 API 已存在，但还没有 20 个真实项目的成本、重试率、配方复用率和人工驳回率数据。
- 适用性诊断到 `evidence/v1` 的自动抽取尚未标准化，当前仍允许人工导入台账。

## 5. 结论

本轮证明：工程门禁和内容登记、诊断、证据、口播草稿、claim/source review 可以稳定运行；尚未证明：未经人工确认的真实稿件能够合法进入配音和 HyperFrames 成片。下一步唯一需要用户决策的是确认三段口播稿，之后继续完成同一个试跑项目，不重新创建另一套视觉体系。
