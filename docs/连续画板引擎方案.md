# 连续画板引擎方案

> 更新状态：2026-07-16 已根据源码调研修订。早期“Motion Canvas 优先”判断已被后续证据取代；当前决策和核验依据见《[端到端开源视频工作流调研](./research/端到端开源视频工作流调研.md)》。

## 第三个参考样本

- 抖音视频 ID：`7662366814240303323`
- 本地分析版本：1280x720、30fps、约 230.78 秒。
- 米色纸张背景、人物讲解员和字幕层持续存在。
- 内容不是逐页切换，而是同一画板上的对象逐步新增、移动、放大、缩小、强调和移除。

连续帧显示：旧标签会停留在画板上，新标签从旁边或下方进入；强调文字短暂放大；观点结束后局部对象淡出或缩小，但画板从不清空。

## 当前模板为什么生硬

当前 `ReferenceStyleVideo` 的核心数据是 `beats[]`，每个 beat 对应一块完整内容。即使移除黑闪，它仍然在替换整组 JSX，因此观感仍接近幻灯片。

目标风格需要长期存在的对象身份和状态：同一个对象必须能跨多段口播继续存在，并从旧位置平滑移动到新位置。

## 推荐数据模型

```json
{
  "canvas": {"width": 3840, "height": 2160},
  "objects": {
    "host": {"type": "character", "asset": "host.png"},
    "tag-api": {"type": "tag", "text": "API 链接"}
  },
  "timeline": [
    {"at": 0, "op": "add", "target": "host", "x": 280, "y": 310},
    {"at": 1.2, "op": "add", "target": "tag-api", "x": 760, "y": 260},
    {"at": 3.5, "op": "highlight", "target": "tag-api", "scale": 1.18},
    {"at": 5.0, "op": "move", "target": "tag-api", "x": 420, "y": 160, "scale": 0.72},
    {"at": 6.0, "op": "camera", "x": 900, "y": 540, "zoom": 1.12}
  ]
}
```

口播稿保持用户原文。模型只能把固定口播片段转换为对象操作和视觉标签，不得生成或改写口播。

## 技术选型

### 推荐：HyperFrames 单 composition + Studio

HyperFrames 已同时提供 HTML/CSS/SVG/GSAP 连续动画、音频时间线、确定性逐帧渲染，以及可回写源文件的 DOM、时间线和关键帧编辑。第一版只需增加“已审稿口播 -> 稳定画板对象/显式 GSAP 关键帧”的薄编排层，不必先自研画板编辑器。

默认 faceless 工作流仍有逐 frame 倾向，不能原样采用。正式工程只保留一个长生命周期 root composition，背景、人物、字幕、画板和相机持续存在。

### 备选：Revideo

Revideo 适合连续场景图和相机动画，许可证友好；但没有与 HyperFrames Studio 同等级的人工微调闭环。只有 HyperFrames 本机实验出现不可接受的渲染或编辑限制时，才制作同稿 Revideo 对照。

### 保留但不作为主线：Remotion / Motion Canvas

Remotion 可以通过绝对时间实现常驻对象，但当前原型必须重写数据模型，且仍需另建编辑层。Motion Canvas 的动画抽象匹配目标风格，但同样缺少现成的用户编辑闭环。两者目前都不优先于已经覆盖渲染与 Studio 的 HyperFrames。

### 不建议

- 继续给现有分页模板增加转场。
- 让模型直接生成任意 JSX 或视频命令。
- 用剪映 GUI 自动化作为核心渲染链。

## 需要确定的输入

1. 最终口播稿。
2. 讲解人物形象：用户提供授权 PNG，或生成一个可商用原创角色。
3. 画板底色、强调色和字体。
4. 是否保留底部烧录字幕。

确定这些输入后，先做 30 秒、6-8 个对象操作的技术样片，验证连续性，再扩展到完整视频。
