# HyperFrames 风格与动效库分享包

> 用途：把本项目中已经沉淀的视觉风格、动效规则、参考素材与调用方式交给其他人，使其能在一个新的 HyperFrames 项目中复建同样的工作流。
>
> 本文是分享包的入口说明。接收方先按「建议目录」放置文件，再按「接入步骤」配置项目；不要只拷贝单个 `index.html` 或某一份风格文档。

## 这份分享包包含什么

| 模块 | 作用 | 是否必发 |
|---|---|---|
| `style-libraries/` | 7 套视觉风格、组件语法、提示词、调用规则及参考图 | 是 |
| `hyperframe-library/` | 真人口播增强的动效分类、文案匹配规则、提示词模板、可复用动效参考 | 是 |
| `examples/` | 已完成的 HTML + GSAP 成片项目，供接收方拆解和验证 | 建议 |
| `workflow-kit/` | 视频任务模板、审查闸门、验收规则 | 建议 |
| `README.md`（本文） | 分享包说明、安装方式与调用规范 | 是 |

不建议发送：`node_modules/`、`.next/`、临时分析帧、原始口播视频、带私人路径的素材、个人账号凭证或缓存目录。它们会使压缩包很大，也无法在对方机器上直接复用。

## 动效库清单

`hyperframe-library/` 目前是“机器可读规划层”，用于把文案语义匹配成合适的屏幕动效，不取代完整的 HyperFrames 视频生产流程。

| 分类 | 用途 | 已沉淀方向 |
|---|---|---|
| `subtitle` | 字幕、关键词强调、结论句 | 底部字幕、重点词、转折字幕 |
| `information_visualization` | 解释关系与数据 | 概念卡、对比、决策表、总结卡；含商业科普发光卡片动效参考 |
| `tool_demo` | 工具与软件演示 | 界面浮窗、Logo 对比、代码/文件窗口、鼠标操作、完成提示 |
| `script_structure` | 口播叙事结构 | 钩子、误区打断、流程拆解、案例、结论；含标题 RGB glitch 参考 |
| `prompt` | 生成调用 | 将模板字段转换成可审查的 HyperFrame 画面描述 |

真人口播项目额外读取：

- `schema/talking-head-effect-template.schema.md`：单个动效模板应具备的字段。
- `matching-rules/talking-head-script-matching-rules.md`：根据文案语义选择动效的规则。
- `prompt-templates/talking-head-screen-description.prompt.md`：把选择结果整理为屏幕画面描述。
- `references/commercial-science-card-motion.md`：发光数据卡、表格、柱状图、比例圆与时间线的入场语法。
- `references/title-glitch-rgb-split.md`：标题 glitch、RGB 通道错位、字形切片抖动的使用边界。

## 接收方的最小接入步骤

1. 创建或打开一个 HyperFrames 项目，并将分享包根目录放在项目内，建议命名为 `hyperframes-style-motion-kit/`。
2. 把 `style-libraries/STYLE_REGISTRY.md` 设为风格入口；每次制作前先读取全局同步标准，再读取被选中的 `STYLE_GUIDE.md`。
3. 为项目加入一个闭合风格选择：编辑型数据简报、苹果、像素卡片、杂志拼贴、黑白赛博、手绘教程。用户没有明确风格时，不自行猜测。
4. 若素材是真人口播视频，再接入 `hyperframe-library/`：先识别文案类型，再从分类、匹配规则和提示词模板中选取增强动效。
5. 按 `workflow-kit/templates/` 先输出可审查的视频任务单，得到确认后再创建 HTML / CSS / GSAP 实现。
6. 用 HyperFrames 的 `lint`、`inspect` 和渲染采样检查：无缺失素材、无溢出、首秒可识别主题、全部口播信息点有对应动态动作。

## 调用约定

### 风格选择

建议项目保留以下固定选择，避免“随便做一个高级感”的模糊沟通：

```text
风格用哪一个：
1. 默认编辑型数据简报风 / 发布会数据报告风
2. 默认苹果风格
3. 像素卡片 UI / 经典平台游戏元素风格
4. 轻量杂志拼贴风 / 动效卡片效果库
5. 黑白赛博编辑风 UI 卡片系统
6. 手绘流程教程演示风格
```

用户明确提到风格名称、别名或编号时，按 `STYLE_REGISTRY.md` 的 Resolution Rule 路由。使用像素风时仅可使用“经典平台游戏符号”作为装饰语言，不使用真实角色、商标或角色肖像。

### 动效实现

- 以 HTML / CSS / GSAP 为默认实现路径；所有时间线确定、可复现。
- 每个口播信息点至少有一个可解释的可见变化：生成、拆分、连接、传递、移动、聚合、数值增长、状态切换、镜头推进或关系高亮。
- 每个场景先确定静态终帧和信息层级，再补动画；不要把动效当成装饰性随机位移。
- 除刻意停顿外，避免连续超过 1 秒没有信息或关系变化的动态死区。
- 禁用 `Math.random()`、`Date.now()`、无限循环，以及依赖在线页面的关键内容；保证渲染可复现。

- [ ] 压缩前确认包内没有 API Key、cookie、账号信息、私人脚本、原始录屏或无授权素材。

## 验收标准

接收方完成搭建后，应能做到：

1. 根据 6 个固定选项选择风格，并定位到相应的风格文档与参考图。
2. 依据风格组件目录和提示词，生成一致的画面设计，而非只复制一张静态图片。
3. 对真人口播文案选择字幕、信息可视化、工具演示或叙事结构动效。
4. 让口播、字幕与画面共用同一时间轴；画面叙事在口播结束前完成收束。
5. 在更换脚本、比例或时长后，仍可用同一套规则稳定产出并通过渲染检查。

## 维护方式

新增风格时，在 `style-libraries/<style-id>/` 下至少提供 `STYLE_GUIDE.md`，并更新 `STYLE_REGISTRY.md`；若需要自动识别，再添加 `manifest.json` 与别名。新增动效时，在 `hyperframe-library/` 先补分类、匹配规则、提示词模板与参考，再把它变成可运行示例。这样分享包会始终是“规则 + 参考 + 可验证示例”的完整集合，而不是难以维护的素材堆。

# 附录 A：可直接复制的完整风格预设

本附录把每个风格的核心提示词、负面限制、可选组件、颜色、运动语法和可粘贴的 `DESIGN.md` 写在一起。接收方无需先在多个文件间来回查找；实际生产时仍以风格目录中的原始文件为准。

## A0. 所有风格共用的硬规则

在任何风格提示词前，先附加这一段：

```text
视频总时长等于口播读完文案的时长。按口播自然语义把画面拆成连续 beat，每个 beat 都要有一个可解释的视觉变化：对象生成、拆分、连接、传递、移动、聚合、数值增长、状态切换、镜头推进或关系高亮。前一句的对象应尽量交接到下一句；不要提前展示完整画面后等待旁白。除刻意的重点停留外，不能有连续超过 1 秒的无信息动态死区。最后一个关键动作必须在口播结束前完成，并保留可读的终帧。
```

通用实现约束：使用 HTML / CSS / GSAP；先完成静态终帧，再制作进入动画；元素用 `data-start`、`data-duration`、`data-track-index` 与口播共用时间轴；场景 timeline 使用 `{ paused: true }` 并注册到 `window.__timelines`；禁用 `Math.random()`、`Date.now()`、无限循环和不可复现的物理模拟。

## A1. `editorial-data-report`：编辑型数据简报风

### 可直接调用的完整提示词

```text
冷灰白的编辑型数据简报动效，不是 PPT，也不是科技 HUD。每一页都像同一本研究报告：顶部有小号章节标签、细横线和页码；正文从一条短红线启动，再出现左对齐的大号黑色标题，只有核心判断中的一个短语用信号红。中部只摆放一套证据结构，例如模块拼接的大数字、三张分类卡、横向排行榜、方块规模集群，或带红色左边线的证据注释框。数据按阅读顺序逐层建立，最后在下方出现一句黑红混排的结论。画面保持大面积留白，颜色严格限于黑、红、灰，并局部使用黄或蓝表示类别。场景转场先淡回浅灰白纸面，再由下一页红线和标题建立。
```

负面提示词：

```text
不要深色背景，不要透明黑玻璃 HUD，不要霓虹发光，不要赛博网格，不要 3D 金属物，不要人物口播主体，不要弹跳、旋转、全屏横移、粒子，不要满屏小字图表，不要所有元素同时进入，不要无来源的伪数据。
```

### 视觉令牌与版式

| 项目 | 规定 |
|---|---|
| 画布 | `#F4F7F4` 冷灰白；预留大面积负空间 |
| 文字 | `#0C0D0D` 黑色；短语级重点用 `#D9274D` 信号红 |
| 类别色 | `#FFD526` 黄仅标记一个单元/引用短语；`#347FB8` 蓝仅作第三类别；非重点为 `#BFC4C2` |
| 固定框架 | 顶部 9% 留给章节标签、细横线、页码；所有页面共用左对齐网格 |
| 信息层级 | 红短线 → 标题 → 证据 → 来源/解释 → 一句结论；一页只讲一个论点和一组证据 |

### 组件与动效配方

| 组件 | 使用场景 | 动效 |
|---|---|---|
| Report Chrome | 章节标签、日期/主题、页码、顶部分隔线 | 首次建立后保持稳定，是跨页锚点 |
| 模块数字 Hero | 版本、日期、数量、发布节点 | 黑色方块按数字笔画组 0.7–1.1 秒组成；再出现说明标题 |
| Claim Headline | 每个新论点 | 红线 220ms 从左画出；60ms 后标题 `y:18→0`、透明度进入 |
| 分类卡 | 三方比较、模型阵容、分类定义 | 白卡+彩色顶帽，按阅读顺序 90ms 错开入场 |
| 横向排名条 | benchmark、成本/性能比较 | 条形从左向右 650ms 生长；数值在条形落位后淡入 |
| 证据注释 | 纠偏、引用、限定条件 | 先白框和红左边线，再出文字，最后黄笔划过短语 |
| 规模集群 | `1 → 4 → 16` 等规模关系 | 黑单格、红色 2×2、蓝色 4×4 逐组组成 |
| 结论 | 页面记忆点 | 所有证据完成后再出现；结论短语用红色 |
| White-out 转场 | 报告页切换 | 旧内容 360ms 淡至底色，停 100–140ms，再从红线开始新页；绝不整页横移 |

推荐时序：兄弟元素错开 60–120ms；标题 420ms，正文 300ms，卡片 360ms，结论 400ms。只用透明度、短距离位移、确定性宽度增长和线条绘制；不使用弹性、旋转、粒子和永久动效。

### 可粘贴的 `DESIGN.md` 块

```markdown
### 视觉方向
- 风格库：`editorial-data-report`
- 背景：冷灰白报告纸面，顶部保留章节、细分隔线与页码。
- 核心视觉：红色短线启动标题；黑红混排论点；模块数字、数据条、分类卡、证据注释框与一句结论。
- 色彩：`#F4F7F4` 背景、`#0C0D0D` 主文字、`#D9274D` 论点与重点、`#FFD526` 局部标记、`#347FB8` 第三分类、`#BFC4C2` 非重点数据。
- 动效：先红线、后标题、再证据，最后落结论；条形图由左向右生长；场景之间白底淡退。
- 不要做：HUD、深色玻璃、赛博霓虹、弹跳卡片、全屏滑页、密集仪表盘。
```

## A2. `apple-clean-product`：苹果风格

### 可直接调用的完整提示词

```text
Apple keynote product-page style, white-to-soft-silver background, floating glass cards, precise blue emphasis, SF Pro-like typography, generous whitespace, smooth push-in motion, clean UI workbench, premium and calm. No real Apple logo, no cyberpunk, no neon particles, no dark tech HUD, no PPT page flips.
```

### 预设规则

- 背景只使用 `#F5F5F7`、`#FFFFFF`、`#EEF1F5` 的白到柔银层次；边框为 `rgba(0,0,0,0.08)`。
- 主字 `#1D1D1F`，次字 `#6E6E73`，唯一主强调色为 `#0071E3`，必要时用 `#D7F1FF` 作为软青高光。
- 使用干净的浏览器/应用窗口、悬浮玻璃卡、产品工作台与大留白；字体使用 SF Pro 相近的 `Noto Sans JP` / `Segoe UI` / `Arial` 无衬线回退。
